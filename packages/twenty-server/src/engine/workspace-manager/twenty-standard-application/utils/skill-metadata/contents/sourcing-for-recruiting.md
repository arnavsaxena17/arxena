## For recruiting

The request is candidates for a role. The core list is the project's People tab. Load this section, then `rubrics` and `playbook-recruiting-admission`.

### The brief, in recruiting terms

- **Role**: title words, level, and the title synonyms you will search.
- **Must-haves a profile can show**: title, employer type, industry, city, skills, years of experience.
- **Later checks** (never fitment criteria):

{{include: later-checks}}

- **Reality-check clauses** ("most have only worked on non-regulated products", "most want private practice"): name the risk to the user in one line. Do not relax a must-have because of it.

### Which track

| The request | Track |
| --- | --- |
| Companies named ("Swiggy and Zomato category heads") | `people-by-company`. Two companies give at most six people, so build peer companies first when the target is larger |
| A title in an industry and a city | `people` |
| A title across an industry, no companies named | `playbook-company-first` |
| Mid-level or plant-level roles | `people`, and `src-naukri` when the user has the Naukri extension connected |
| Applicants to a posting | Score on the People tab (`inbound-applicants` + `scoring`). No search finds them |

Say the track and the reason in one line.

### Rules

- **Age** follows the age policy above. Mention in the assumptions line that it was ignored.
- **Doctors and other qualified specialists**: count experience from the qualification date. Profile coverage can be thin; say what you do not know and probe first (`query-planning`).
- Every report ends with the funnel counts, the spend, and the later checks still open.
