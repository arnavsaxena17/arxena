## Source profiles

System facts the model cannot know. Each line is tagged **firm** (measured or set in code), **heuristic** (experience, not measured) or **illustrative** (an example to calibrate on, not a promise). Quote a heuristic as "usually", never as a number. A source not listed here is switched off.

### Staleness by field

- **Current role and employer**: heuristic, LinkedIn lags on job changes in India. A role ended over a year ago with nothing newer is probably stale.
- **Location**: where the person lives, not company HQ. Reasonably current.
- **Company size, revenue, store counts**: heuristic, treat as a band, not a figure. A web column beats the profile when it matters.
- **Skills**: self-declared. Evidence only when an experience entry backs them.

### Web search routing

Not benchmarked yet: do not claim one engine is better. Until it is, use the order in `research`; on a probe, run the same query on two engines and report the measured overlap.

### Hyperlocal recipe

illustrative, untested: Google location search for the places, Bright Data for the company record, LinkedIn for the people. Probe on one city before scaling.

### Exhaustion

A source whose last batch is over 80% duplicates, or that reports no more pages, is exhausted for this query (`playbook-shortfall`). Repeating a query returns only rows already in the list; change the title words, the city or the size band.
